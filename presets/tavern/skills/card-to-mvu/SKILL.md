# 人物卡转 MVU

目标：正文模型写剧情；后台 Agent 根据本轮实际正文与当前变量快照提交更新；宿主官方 MVU 结算；固定状态视图读变量并自动刷新。MVU 是运行约定，不是新的卡文件格式，成品仍是人物卡 JSON/PNG。

## 1. 找出原来的状态协议

空白工作台先定位源卡文件；调用 `tavern_read_card` 或 `tavern_read_card_raw` 时显式传入源卡的 `path`，不依赖尚不存在的当前正式人物卡。使用文件工具时直接读取已确认的源卡路径。

检查 description、开场白及 alternate_greetings、mes_example、system_prompt、post_history_instructions、世界书、正则与 Helper 脚本。搜索状态代码块、HTML、占位符、数值规则、要求每轮重复档案的指令，以及候选行动生成要求和对应展示、脚本。默认保留无关字段、扩展、署名及 `{{char}}` / `{{user}}`。

交付一份简短字段映射：**旧显示项 → 变量路径 → 类型/初值 → 变化依据 → 展示位置**。区分：

- 稳定档案：身份、外貌等保持已有事实，不在每轮重新编造。
- 可变状态：位置、衣着、任务等按正文已发生的事实更新。
- 推导值：只迁移原卡明确的公式，列清由脚本还是后台负责，避免重复结算。
- 未知信息：采用适合字段类型的未知值，并在 UI 显示“未明确”；没有依据的好感、内心、计时规则不新增。

已经有 MVU 时先识别并复用初值、Schema、脚本和视图，不再装第二套核心。需要复杂约束时保留原 Schema；从零简单转换可使用官方 MVU 的初值 Schema，无需额外 Zod 脚本。

完成条件：知道状态要求藏在哪里、哪些要替换、哪些必须保留。说明转换方案；用户已明确授权转换且原卡唯一时继续，不重复索取同一授权。已有游玩记录不随卡片转换自动迁移。

创建副本前，读取原卡实际生效的世界书绑定及其内容，区分自带、外部和明确不绑定；卡内有条目不等于运行时会使用它们。

## 2. 先创建 MVU 副本

原卡作为只读来源，转换只在独立副本上进行，不能先改原卡再另存。

批量变换时解析副本 JSON 后按字段修改，完整保留无关字段，再序列化保存。保存后重新解析并比较原卡与副本，核对仅有预期字段发生变化。

1. 调用 `tavern_copy_card`，传入原卡 `path` 和「原卡名 MVU版本」作为 `name`。工具创建独立路径和资源 ID；重名时另选名称，不覆盖已有资源。
2. 工具自动保留源卡 PNG，核对返回的 `imageCopied`。后续编辑使用返回的副本 `path`。
3. 重新读取已保存的副本，确认它与原卡是两个独立资源，再把后续写入目标设为副本。若工具只会修改当前卡，必须确认当前目标已切到副本；无法切换时直接使用文件工具修改副本，不能向仍指向原卡的工具提交变更。
4. 副本创建或目标确认失败时停止写入并说明原因。原卡实际使用外部世界书时，将所需原有内容复制整合到副本自带世界书，保留条目顺序、启用状态及触发设置，再加入 MVU 条目；保留原卡内其他无关内容，合并时处理条目 ID 冲突。原卡明确停用的普通条目不自动重新启用。原世界书及其他共享资源保持不变。

完成条件：副本实际存在且可读取；源卡有图时，副本在人物卡库可显示同一封面，并可导出带转换后数据的 PNG。后续写入明确指向副本，原卡及其共享资源保持不变。

## 3. 拆分状态职责

开始实现时读取 [MVU 配方](references/mvu-recipe.md)，按实际字段改写示例，而不是照搬示例世界设定。

1. **初值**：内嵌世界书 `[initvar]` 条目存变量对象；关闭普通正文注入。选择一个开场建立一致初值，多开场具有不同状态时明确初始化策略并分别验证，不让所有开场误用同一状态。
2. **规则**：将状态变化依据写进启用的 `[mvu_update]` 条目，交给后台 `mvu_submit_update`。规则路径、类型、新增对象结构必须与初值/Schema 一致；需要新增人物或任务的集合显式可扩展。
3. **正文**：移除已被替代的“末尾输出状态表/变量协议”要求及对应旧示例、旧正则，保留叙事设定、玩家视角、文风和无关剧情规则。description、system_prompt、post_history_instructions、开场白及示例等前台提示字段只做必要清理，不追加 `<mvu>` 说明、后台结算或独立面板介绍，也不补写“只输出剧情正文”“不要输出 `<UpdateVariable>` / JSON Patch / 变量更新说明”等替代指令，或“禁止代码块”等通用格式限制。已有转换遗留的此类说明和替代指令在副本中直接删除，包括“变量更新由正文提交后的后台 Agent 独立结算”等表述，不再换一种说法补回；前台所需的剧情事实和当前状态仍保留。初值与更新规则只放入专用世界书条目；从原位置直接删除已迁移内容及其空标题、空容器，不留下“已迁移至后台”“由 MVU 管理”等替代说明、注释或占位文字。下一项所需的展示入口保留，并从模型历史中移除。
4. **视图**：用固定 HTML + Helper 读取最新消息的 `stat_data`，监听更新事件；由宿主提升到右侧持久面板。使用配方的 `<mvu-status/>` 声明入口和具有固定、唯一 `id` 的显示正则；编辑 HTML 或调整顺序时保留该 ID，不复制成第二条启用的面板规则。开场的一次入口通过显示正则挂载，另用 promptOnly 正则从模型历史移除。每个可选开场均检查入口，正文模型不负责每轮生成入口或 HTML。

保留原有视觉意图，换掉数据来源即可。没有合适布局时，可先适配 [只读状态视图](assets/status.html) 跑通数据，再按原卡字段布局；该模板不是要求所有卡统一外观。固定面板不使用 EJS 读取动态状态或执行副作用；每次重绘通过 Helper 读取最新快照。文本用 `textContent` 渲染；视图只读，不自己请求 LLM 或回写变量。原卡复杂交互的迁移需要单独识别其写入职责。

转换不自动改写题材或净化故事内容。航空测试中的内容净化是那次单独授权，不是转换的通用步骤。

## 4. 专项检查：删除卡内候选项生成机制

DSH Tavern 自带候选项生成。转换后的副本只使用宿主这套机制，必须检查并清除原卡自带的候选项生成及其专用展示实现。

1. **逐处检查**：检查 description、system_prompt、post_history_instructions、first_mes、所有 alternate_greetings、mes_example、世界书条目、正则、HTML 和 Helper 脚本。搜索“候选项、候选行动、行动建议、下一步、选项、choices、options”等线索，再阅读上下文判断用途；不能只检查主描述或只搜一种叫法。
2. **删除生成要求**：删除副本中重复的生成要求，包括“每轮给出若干行动”“正文末尾列出可选回复”等指令、数量与格式约束、候选项输出协议、对应示例和开场白中的候选列表。专门存放这类要求的世界书条目直接删除；混合条目只删相关部分。
3. **删除配套实现**：删除用于提取、渲染或提交这些生成候选项的专用正则、HTML、按钮、事件监听和自行请求模型生成候选项的脚本。共享组件只移除相关逻辑，保留状态栏及其他交互；无法确认能否安全拆分时报告具体位置，不整段盲删，也不标为清理完成。
4. **直接清空原位置**：清理后删除空标题、空容器和失效引用。不把候选机制迁移进 MVU 变量、初值或后台更新规则；不补写“由宿主生成候选项”“不再输出选项”等说明、注释、占位文字或替代指令。
5. **保留剧情交互**：保留剧情中的选择、分支条件与实际游戏交互，例如开局路线选择、固定剧情分支或道具操作。判定依据是它是否服务于自动生成的候选行动，不能仅凭“选项”字样或存在按钮就删除。

完成条件：重新读取已保存副本，复查上述字段及脚本；确认生成要求、示例、协议和专用展示均无残留，没有迁移说明或空壳，原有剧情分支与无关交互仍保留。验收报告单列“候选项清理”，列出删除位置和保留的剧情交互；原卡没有候选机制时写“已检查，未发现”，存在未解决项时如实列出。

## 5. 保存与验证

保持卡片自包含：初值、规则、正则和 HTML 写进成品卡。旁边的明文源文件用于维护，不应成为导入后的隐含本地路径依赖。已有工作区包装格式用环境的导入/导出能力处理，避免拿外部 V3 JSON 覆盖内部工作区对象。

为副本明确绑定自己的世界书，不沿用原卡的“不绑定”状态或仍指向原资源的绑定。使用当前环境实际可用的绑定能力完成操作，然后回读副本的实际绑定目标，并从该目标读取新增的 `[initvar]` 和 `[mvu_update]` 条目；不能仅凭卡内条目数量判断已经生效。

若当前环境无法完成绑定，保留已生成副本，明确报告“副本已生成，世界书绑定尚未完成”，给出副本名称、世界书名称和手动绑定步骤，等待完成后继续验证；不能宣称转换全部完成。绑定调整只作用于副本，不修改全局默认规则或原卡的绑定选择。

分开报告这些验收结果：

- **静态**：成品能重新解析/导入；核对原卡与转换前内容一致，成品保存在独立的 MVU 副本中；无关字段保留；路径类型一致；规则分流到后台；前台提示字段没有新增或遗留的转换运行说明，原位置没有迁移占位文字或空壳；卡内重复的候选行动生成及专用展示已移除，剧情选择和交互仍保留；模型历史没有状态入口/HTML，正文显示仍完整。
- **绑定**：副本实际绑定自己的世界书，从绑定目标可读取正确的初值和更新规则，原有有效世界书内容仍保留；原卡与其他资源的绑定未变。
- **初始化**：独立测试对话使用转换卡；官方 MVU 初始化完成，右侧能显示初值。别用旧对话已保存的变量证明新卡初始化成功。
- **展示**：开场与推进后都只有一个右侧状态面板，正文没有第二份面板或其折叠/源码工具栏。调整酒馆正文字号，确认面板跟随缩放且无跳变；切到其他会话再切回、重新打开测试对话后再次检查。修改固定 HTML 并调整显示正则顺序后，应仍只有一份面板，采用新模板、保留当前变量；不靠清空历史或重新生成正文通过验收。
- **真实更新**：正文确认一个状态变化，核对工具实际提交、结算成功/失败项及落库值，右侧在不手动刷新的情况下显示新值。思考文字和 `accepted: true` 都不是结算成功凭证。
- **边界**：至少检查一次无变化回合、一个可扩展集合新增，以及回退或重新生成后的状态对应关系。没有实测的项目明确标为待验证。

使用获准的测试对话/模型请求；若当前工具不能操作游玩界面，交付卡片并给用户简短验证步骤，不声称完成真实验收。仅创建 Skill 本身不触发游玩或改写任何人物卡。

## 失效时先分层

- 后台没有提交：先查副本实际绑定的世界书是否包含更新规则，再查规则是否以 `[mvu_update]` 开头且启用、是否进入后台上下文，而不是把思考中的计划当提交。
- 提交但未生效：查实际回执、JSON Pointer、数据类型、Schema 和集合扩展规则；区分部分失败、无变化、脚本派生变化。
- 面板重复或改样式后跳变：检查显示正则 ID 是否唯一且保留、入口是否为配方声明、是否还残留旧状态正则或直接内嵌的旧 HTML。读取 `Mvu.getMvuData` 本身不声明侧栏用途。保存源消息、显示缓存和规则供诊断，不删除历史缓存或重跑历史 EJS 来掩盖问题。
- 已落库但右侧不刷新：查 Helper 快照、事件、iframe 就绪及宿主增量同步。已知宿主问题可导致此症状；不要用重新生成 HTML、轮询或视图写变量掩盖。
- 本 Skill 面向 DSH Tavern 的官方 MVU 后台工具路线。原生 SillyTavern 的依赖和额外模型配置另行验证，不宣称可直接跨宿主运行。

完成时交付目标卡路径、迁移字段、保留/替换内容、已通过与待验证项。宿主修复和历史数据迁移超出单卡转换时先说明，再按用户授权处理。
